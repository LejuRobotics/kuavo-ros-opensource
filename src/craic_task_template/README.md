# 第二十八届中国机器人及人工智能大赛 - 仿真赛评分细则

总分：**120 分** | 每场景单次限时：**10 min** | 成绩 = 两场景单次最佳分数之和

> **评分方式**：本次仿真赛采用**人工评分**。代码提交截止后，举办方使用统一随机种子运行各队提交的代码，由裁判根据机器人在仿真环境中的实际表现，按照以下细则逐项评分。

> **完整通过**：机器人在通过该区域的过程中，双脚始终保持在区域范围内（任一脚踩出区域边界即视为未完整通过），且双脚均离开该区域到达另一端。离开区域后 3 秒内未摔倒方可得分。

---

## 场景一：安全巡检（50 分）

### 赛项任务（30 分）

**路线**：起点(3m×3m) → 障碍区 → 复杂地形区 → 操作台1 → 斜坡区 → 台阶区 → 操作台2 → 终点(2m×1m)

| 得分区域 | 分值 | 通过条件 | 备注 |
|---------|------|---------|------|
| 台阶区 | **10 分** | 完整通过，离开后 3s 内未摔倒 | 四级台阶，每级 0.28m×1.5m×0.13m |
| 斜坡区 | **6 分** | 完整通过，离开后 3s 内未摔倒 | 斜坡 2m×1.5m×0.52m + 平台 1m×1.5m |
| 复杂地形区 | **6 分** | 完整通过，离开后 3s 内未摔倒 | 石子路 + 减速带(0.35m×2m×0.05m) + 颠簸路段 |
| 障碍区 | **4 分** | 完整通过，离开后 3s 内未摔倒 | 6 个路障(直径 0.33m，高 0.6m)随机放置 |
| 触碰障碍物 | **-2 分/次** | - | 超过两次后通过障碍区不得分 |
| 按钮操作 × 2 | **2 分/次** | 正确按下对应颜色按钮熄灭灯光 | 每台只能按一次，按错/多按/未按均失败 |

### 附加任务（20 分）

赛项完成后由机器人**自主决策**是否挑战（禁止人工干预），无需按钮操作。

**路线**：终点 → 台阶区 → 斜坡区 → 复杂地形区 → 障碍区 → 起点

| 得分区域 | 分值 | 通过条件 |
|---------|------|---------|
| 台阶区 | **8 分** | 完整通过，离开后 3s 内未摔倒 |
| 斜坡区 | **5 分** | 完整通过，离开后 3s 内未摔倒 |
| 复杂地形区 | **5 分** | 完整通过，离开后 3s 内未摔倒 |
| 障碍区 | **2 分** | 完整通过，离开后 3s 内未摔倒 |
| 触碰障碍物 | **-1 分/次** | 超过两次后通过障碍区不得分 |

## 场景二：分拣归档（70 分）

### 料盘下架（40 分）

从料盘架（三层，1.2m×0.4m×1.5m）夹取料盘放入置物架上的物料箱中。

| 得分项目 | 分值 | 满分 | 备注 |
|---------|------|------|------|
| 夹取**最下层**料盘 → 物料箱 | **13 分/个** | 26 分 | 共 2 个，料盘重心需在箱内 |
| 夹取**中间层**料盘 → 物料箱 | **7 分/个** | 14 分 | 共 2 个，料盘重心需在箱内 |

### 分拣零件（30 分）

工作台（1.4m×0.8m×0.8m）上两种零件各 3 个，分类放入两侧物料箱。

| 得分项目 | 分值 | 满分 | 备注 |
|---------|------|------|------|
| 正确放入零件 A | **5 分/个** | 15 分 | 该箱内不能混有零件 B |
| 正确放入零件 B | **5 分/个** | 15 分 | 该箱内不能混有零件 A |
| 错误分类 | **0 分** | - | 混放则该箱所有零件均不得分 |

---

## 任务结束条件（任一满足即结束）

1. 机器人重心移出当前场景区域（离开赛道）
2. 机器人摔倒
3. 选手手动选择结束

## 排名规则（依次比较）

1. **总分**高者优先
2. 总分相同 → **分拣归档分数**高者优先
3. 均相同 → **分拣归档用时**少者优先
4. 全部相同 → 并列

## 比赛注意事项

- 初始朝向位置**随机**，需自主导航定位
- 全程**自主导航 + 自主决策**，禁止人工干预
- 每个得分区域/操作台仅能得分**一次**
- 代码提交后使用统一随机种子，每个赛项任务仅进行**一次**

# 代码提交规范

## 提交方式

通过报名系统提交附件，附件命名格式：**`参赛团队名称+人形机器人创新挑战赛`**

## 提交内容

基于官方提供的模板功能包 `craic_task_template` 进行开发，功能包名称固定不变，外层以 **`参赛团队名称+人形机器人创新挑战赛`** 命名打包提交。

### 情况一：使用仿真环境自带控制器（不修改控制器）

```
参赛团队名称+人形机器人创新挑战赛/
└── craic_task_template/            # 功能包名称固定
    ├── CMakeLists.txt
    ├── package.xml
    ├── scripts/                    # 任务脚本目录（必须）
    │   ├── scene1_patrol.py        # 场景一：安全巡检任务脚本
    │   └── scene2_sorting.py       # 场景二：分拣归档任务脚本
    ├── launch/                     # launch 文件（可选）
    ├── src/                        # 其他源码（可选）
    └── README.md                   # 运行说明
```

### 情况二：自行修改控制器

除 `craic_task_template` 外，还需额外提供修改过的相关功能包：

```
参赛团队名称+人形机器人创新挑战赛/
├── craic_task_template/            # 任务功能包（必须）
│   ├── CMakeLists.txt
│   ├── package.xml
│   ├── scripts/
│   │   ├── scene1_patrol.py
│   │   └── scene2_sorting.py
│   └── README.md                   # 需说明修改了哪些功能包及原因
└── humanoid_controllers/           # 示例：修改过的控制器功能包
    └── ...                         # 仅包含修改过的功能包，保持原包名
```

- 修改过的功能包保持原名，将直接替换仿真环境中的同名功能包
- 必须在 `README.md` 中说明修改了哪些功能包、修改内容及编译方法
- **必须确保**修改后的功能包可以在官方 Docker 环境中正常编译运行，否则视为对应任务失败

### 通用要求

- 功能包将被放置到仿真环境的 `src/` 目录下，与 `craic_simulator` 同级，通过编译运行
- 必须包含 `scripts/scene1_patrol.py` 和 `scripts/scene2_sorting.py`，缺失则对应任务失败，正式比赛将运行这两个程序完成评分
- 如需额外依赖，请在`README.md` 中注明

## 提交要求

1. **环境兼容性**：代码在官方提供的 Docker 容器（Ubuntu 20.04）中运行，请确保代码兼容该环境
2. **接口合规**：请遵守"严禁事项"中的规定，机器人应通过自身传感器和控制接口完成任务
3. **自主运行**：提交的代码必须能够自主完成全部任务流程，不依赖人工干预
4. **命名规范**：附件命名必须符合 `参赛团队名称+人形机器人创新挑战赛` 格式，不符合视为未成功提交
5. **截止时间**：必须在代码截止日期前完成提交，逾期视为自动弃权

## 严禁事项（违规取消成绩）

比赛时系统将自动检测违规行为，一经发现**取消该场成绩**：

1. **严禁直接修改物品位置** — 物品必须通过机器人物理操作（抓取、搬运、放置）来移动，不得通过任何方式跳过操作过程
2. **严禁对机器人施加非物理外力** — 机器人运动必须依靠自身关节驱动，不得通过额外手段辅助
3. **严禁操控仿真运行状态** — 不得暂停、加速或以其他方式干预仿真进程
4. **严禁读取真值信息** — 机器人应通过自身传感器（雷达、IMU 等）感知环境，不得直接获取物体的绝对坐标
5. **严禁修改仿真环境文件** — 不得修改 `craic_simulator` 包中的场景文件、launch 文件或其他配置
