# MR !4194 复核与范围修正（2026-10-31）

## 发现和修正

1. 原 MR 不满足“只修改绝对式”的范围要求：包含共享 CAN/SG100、增量接收端、公共头部节点、公共增益/录包列表。现将所有包外路径逐文件恢复为 beta `2e5f9d821`；头部算法和增益移到私有包，驱动增强退出本 MR。
2. 原首次启动检查只在操作服务外层，内部操作仍可被其他调用路径使用。现将首次/后续规则下沉到操作入口；只有真实双前扳机分支能标记首次请求，且禁止把手柄请求在等待期间变成裸手启动。
3. 旧 `/quest3/triger_arm_mode` 的恢复分支仍能直接调用会话创建。现正式绝对式模式忽略外部模式 1/2；经过操作入口的内部故障重授权走有期限、来源和代次校验的事务；模式 0 的停止保留。
4. 原始 running 手势沿能直接排队跟随。现仅消费连续 OK 判定发放的当前代次一次性裸手授权；控制器 running 标志不能启动，既有操作事务和停止沿不受影响。
5. X+B 曾与 X+A 共用启动服务，模式 0 下可能创建新会话。现私有 FSM 将 X+B 发往 arm_hold_operation，只允许 ACTIVE 会话保持/续接；X+A 继续使用普通操作服务。
6. 撤回公共接收端改动后，record-only 轨迹不能继续发到公共命令话题。现新增录制输出全部隔离到 `/whole_body_velocity_ik/record/`，并更新绝对式录包器和实际发布回归。

## beta 修复保留依据

- 包外最终净差异为零：包含共享控制器/躯干零输入与切组、增量 yaw、急停、CAN/dexhand/SG100 和公共头部节点。
- 私有头部子类仅覆盖初始化活动量对象与活动量偏置计算，沿用 beta 的全部模式切换、超时和限位方法，不修改公共模块全局对象。
- RNEA 后端及参数、J3 专用配置、平台 CPU 分区、SHM 接管/租约、严格新鲜度与终止机制保留；移植输入算法时继续通过原有回归。
- X+A 准备/中断、X+B 原会话保持/续接、独立底盘、光学 50 帧/来源锁定/新执行权、Pico 输入、模型/限位和急停回归继续通过。

76 组绝对式 CTest 全通过。新增入口测试涵盖首次服务/内层操作拒绝、等待失败重试、执行确认后禁止扳机重启、旧话题阻断、原始 running 阻断、使能/反馈不授权、X+B 不建新会话、来源切换取消，以及首次裸手 OK 正常启动。C++ 生产按键分支验证 X+A/X+B 分别使用正确服务。

## 静态检查复核

流水线 402654 的新增项为录制 GTest 在匿名命名空间内触发 cppcheck 1.90 解析错误、条件编译下录制初始化被误判未使用、回调计数被误判不变。将 GTest 注册放到全局作用域，抽取生产/测试共用的录制 publisher 初始化函数，并使用 atomic 回调计数；断言与隔离检查保留。

同版本 cppcheck 1.90 执行仓库原脚本扫描 4062 个源文件，通过原基线：style 7498/7498、error 77/77、warning 237/618，其余类别不超基线；没有修改 CI 配置或提高基线。最终 IK 和录制测试重新编译通过，四项录制单元测试及四模型隔离录制联调再次通过。
