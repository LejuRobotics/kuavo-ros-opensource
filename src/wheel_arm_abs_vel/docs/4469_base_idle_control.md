# #4469 初始化待机时控制底盘

日期：2026-10-21。yyb 工作区 `/home/yyb/workspace/kuavo-abs-controls-issues-20261021`；分支 `codex/abs-controls-issues-20261021`；本轮基线 `ac4761feb`。

问题：Pico 连接后，底盘必须先解锁手臂才能响应。预期：初始化完成且底盘总锁已关闭后，可直接用摇杆移动，无需先按 X+A 解锁双臂。

参考 dev `f0ff59191` 的 Pico 说明：5W 使用独立轮臂摇杆分支，无需双足 B 踏步；“遥操锁定、身体控制范围、手臂算法”是不同概念。沿用用户确认的独立绝对式按键，不额外移植 LT+LG 解锁方案。

## 修改

- Mapper 原来要求手臂 ACTIVE；现在允许初始化后的 WAITING/WAIT_RELEASE 等稳定状态，以实时机器人观测、关节反馈、控制使能和模式稳定作为底盘输入条件。接管／准备过程、停止、故障仍关闭输出。手臂 `_fixed_operation_block` 不再代替底盘使能。
- 执行器原来要求正在应用新鲜的 ACTIVE IK 参考；新增有效待机姿态保持、没有 IK 所有者且 authority=INACTIVE 的入口。已有所有者仍必须通过原新鲜度与制动检查；失效所有者不能通过待机路径继续输出。
- 保留 `base_locked`、底盘急停、控制软暂停、速度限幅、加速度限制和 0.2 秒输入超时。状态变更不刷新缓存命令，权限恢复后须收到新摇杆包。
- `base_locked` 默认仍是 true；使用底盘时须在控制器入口设置 `base_locked:=false`。本次未修改实际运行参数或启动机器人。
