## #4481 当前问题与修改后的行为

原问题：在躯干控制模式按 X+B，手臂和躯干一起锁住。原因是按键策略撤销 torso 标志，且 `_fixed_arm_operation(0)` 结束整个绝对式会话并调用底层 HOLD。

修改后的操作：

1. 2026-10-22 更新：启动后首次有效跟随默认开启躯干；保留 Quest/Pico 组合键关闭或重新开启。X+A 复位仍撤销躯干权限。
2. 此时按 X+B：双臂按已有加速度约束减速保持，躯干继续跟随；保留同一个执行所有者、session/generation 和躯干零点。
3. 再按 X+B：恢复原绝对式双臂映射，躯干继续控制。没有改成增量算法，也不重标定躯干。
4. 双臂暂停时可以关闭躯干；关闭后双臂仍保持。再次 X+B 只恢复双臂，不自动重新开启躯干。
5. 暂停状态下 X+A 进入准备动作并关闭躯干。停止、失联、模式改变和故障仍按全身停止链路处理。
6. 躯干未开启时 X+B 保留原来的全会话暂停／恢复行为；这次没有放开底盘权限或变更 #4469。

实现落点：

- `torso_controls.py`：X+B 不再等同于 X+A 的权限复位；保留冲突消费与停止优先级。
- `ik_ros_velocity.py`：健康躯干会话内使用手臂暂停子状态；恢复检查输入、反馈、控制使能、停止／故障与执行所有者。依赖不健康的暂停请求回退为原全身 HOLD。
- `TeleopTcpTarget.msg`：同帧传递 `arm_hold` 和单调的 `arm_operation_seq`。新消息须与节点一起重新构建。
- `pinocchio_velocity_ik_node.cpp`：正常求解和安全监督共同约束 14 个手臂关节的减速／保持，躯干约束按独立权限处理；同一骨骼时间戳的暂停指令可生效但不会刷新观测时间，旧操作不能覆盖新操作。
- 离线回归目标补齐对生成消息的构建依赖，避免并行构建时读到旧消息头。
