# 绝对式 Quest / Pico 输入与终端确认

> 2026-10-31 复核：本 MR 最终仅修改绝对式私有包，共享/增量改动已撤回。当前规则：手柄首次只用双前扳机，首次成功后只用 X+A 重新启动；首次失败仍用双前扳机重试。X+B 仅续接已有活动会话；裸手 OK 启动保留，初始躯干权限统一由 `control_torso` 控制。详见[功能迁移与验证说明](test_beta_port_20261031.md)，下文旧入口描述以此为准。

## 1. 适用范围

适用于 `wheel_arm_abs_vel` 中具有完整 URDF、14 个手臂关节和 4 个躯干关节配置的轮臂机型。Quest 和 Pico 共用 Mapper、速度 IK、手臂操作服务、参考握手及头控处理。输入来源只选择一套。

Quest 无手柄操作不限定 S62；60、61、62、63、200062、210062、300062、310062、400062、400063 使用相同的光学入口。默认 `tracking_source_mode=auto`，首次可直接连续 50 个有效帧保持双手 OK 手势，经过当前模型的目标重捕获、对齐和执行权握手后跟随，不依赖手柄心跳；双手停止手势仍有效。活动会话不直接切换来源，已有手柄会话先完成原有复位流程。各机型使用自己的模型、关节限制和末端配置；S62 目标映射策略不作为无手柄功能的机型限制。

当前 Pico 协议没有裸手骨骼与手势字段，因此该入口的无手柄能力取决于输入设备协议，不能通过修改机型号补出。此次覆盖模型解析、Quest/Pico 参数传递、状态机启动和公共光学启停回归；不代表所有机型已经完成真实裸手跟随验收。

本次按用户最终要求保留 X+A / X+B 操作；不切换到官方 Pico 的 LT+LG / RT+RG 遥操锁方案，也不引入增量、双足踏步、裸手跟踪、音频或继电器节点。

## 2. 按键操作

| 输入 | 操作 | 条件 |
| --- | --- | --- |
| 终端 `o` | 请求初始化 | 默认在第一个控制器终端按；第二输入终端不重复确认。输入端辅助监听仅在显式 enable_terminal_start:=true 时启用 |
| 长按 A | 原有初始化确认 | 尚未收到控制器 observation 时；原有逻辑保留 |
| X+A | 复位与跟随切换 | 跟随 2 → 复位 1；复位 1 → 跟随 2；固定 0 → 复位 1；复位期间再按一次立即中断 PREPARE，保留连续参考并重新捕获跟随；旧代次完成消息被拒绝 |
| Quest X+右摇杆下拉 | 锁定折叠臂及腰部全部跟随，包括 yaw | 手柄输入、人体姿态及跟随会话有效；右摇杆保持超过 100 个新样本，操作后回中 |
| Quest X+右摇杆上推 | 解锁折叠臂及腰部全部跟随 | 手柄输入、人体姿态及跟随会话有效；右摇杆保持超过 100 个新样本，操作后回中 |
| Quest 单独右摇杆下拉 | 锁定折叠臂与腰部俯仰，只保留腰部 yaw 跟随 | 手柄输入、人体姿态及跟随会话有效；右摇杆保持超过 100 个新样本，操作后回中 |
| Quest 单独右摇杆上推 | 解锁折叠臂及腰部全部跟随 | 手柄输入、人体姿态及跟随会话有效；右摇杆保持超过 100 个新样本，操作后回中 |
| Pico RT+Y | 躯干模式开／关 | 输入、姿态及跟随会话有效；RT 超过 0.5 与 Y 组合，先 RT 或先 Y 均支持；释放后才能再次切换 |
| X+B | 暂停／恢复双臂 | 无论是否已开启躯干均只暂停双臂、保留会话；可以先锁手再开启躯干；再次按下限速恢复双臂；复位 1 下不响应 |
| X+Y | 原有软件停止 | 保留 `enable_vr_stop_robot` 开关及现有停止链路 |
| Pico 单独长按 X | 左拇指张开状态切换 | 持续至少 0.5 秒；末端支持对应通道；左右扳机均小于 0.5 |
| Pico 单独长按 A | 右拇指张开状态切换 | 同上；初始化完成收到 observation 后才生效 |
| 双前扳机 | 保留原首次解锁入口 | 两侧超过 0.5 即检测到一次组合；跨帧按齐有效，与 X+A 共用有界就绪等待；已经跟随时仍用于末端操作 |
| 单独 Y、扳机及抓握键 | 末端冻结／夹合 | Pico 的单独 Y 在松开时切换冻结；躯干组合中的 Y 不触发冻结 |

Pico 长按一次只切换一次，必须释放再长按才能再次切换。X+A、X+B、X+Y 等组合优先；组合中途松开另一键不会变成拇指长按。超过 0.25 秒没有新手柄包会取消进行中的长按，恢复后需先释放按键。

长按 X/A 只作用于末端拇指通道，不伪造 `/quest_joystick_data` 的硬件触摸字段。躯干模式按上表的独立组合操作。官方 Pico 的 0.5 秒长按阈值及空闲扳机条件参考：

[Pico 官方使用说明与实现](https://www.lejuhub.com/highlydynamic/kuavo-ros-control/-/tree/dev/src/manipulation_nodes/pico-body-tracking-server)

### 躯干权限与末端冲突处理（#4479）

首次有效跟随的躯干初始选择仍由 `control_torso` 决定，默认 `true`；`false` 启动时锁定折叠臂与腰部，随后可用右摇杆明确解锁。Quest 仅使用上表四种摇杆操作；已删除“触摸 X+Y 后按 B”的躯干切换及其末端按键消费。Pico 原有 RT+Y 操作保持不变。

Quest 右摇杆纵向幅度须超过 0.8，连续超过 100 个新手柄样本后生效（沿用原确认条件）；每次操作后回中至 0.5 以内再进行下一次操作。X 必须按下，触摸不算。四个动作直接选择目标模式，重复同一动作不会反向切换；两种上推动作均解除此前的位置锁定，单独下拉即使从全锁状态也进入仅 yaw 跟随。

X+A 仍切换全身复位／跟随；复位时将腰部、折叠臂与双臂送回配置的准备姿态，清除手动躯干模式，恢复跟随时重新应用 `control_torso` 启动选择。复位仍保留原有执行、时效、故障和轨迹约束。X+B 仍仅暂停／恢复双臂，保留躯干会话与当前躯干模式；按下 X+Y 的软件停止入口保留。

手柄或骨骼短暂断流不改变已选躯干模式，未完成的摇杆操作作废，恢复后先回中。停止和故障继续通过原有链路撤销执行权限；输入恢复本身不构成新的解锁操作。

开启躯干时重新采集当前机器人参考与人体姿态作为零点，不追赶关闭期间的身体位移。关闭时，运动中的折叠机构按现有加速度约束减速至零后保持；静止时直接保持。约束进入求解器和安全监督器，双臂的 TCP 误差也不能越过它。

### 躯干模式中的双臂暂停（#4481）

开启躯干后按 X+B，双臂在已有加速度约束内减速并保持关节姿态，躯干继续跟随。保持的是手臂关节：躯干移动时手臂会随躯干整体移动，不表示手部在世界坐标中悬停。

再次 X+B 恢复原绝对式手臂目标，沿用原映射和速度／加速度限制，不重新采集躯干零点。暂停时移动过手柄，恢复后双臂会继续趋向当前绝对式目标；这不是增量重定位功能。

双臂暂停时也可以操作躯干开关，关闭躯干不会自动恢复双臂。此时 X+A 进入全身准备动作并暂停人体躯干跟随，恢复时应用启动选择；停止和故障仍沿用原有停止链路。恢复双臂需要新鲜输入、有效反馈及健康执行所有者。未开启躯干时 X+B 同样保持双臂关节并保留会话，随后仍可开启躯干。

状态话题 `/quest3/pinocchio_arm_operation_state` 的 0/2 表示操作员的双臂暂停／跟随意图；躯干会话中的底层执行所有者仍保持 mode 2。实际是否已经停稳须检查关节速度，服务受理不等于物理动作完成。

Pico RT+Y 支持两种顺序。先 RT 时，首次超过 0.5 后给出 150 ms 组合仲裁窗口，窗口内到来的 Y 会消费本次夹爪动作；先 Y 时直接保持先前夹爪指令。若 RT 单独持续超过窗口，正常夹合已发出，此后补 Y 会保持已发出的值，不能事后撤销。组合及松开阶段消费 Y，不触发末端冻结；释放 RT 后再次单独捏下恢复夹爪控制。

`/quest3/torso_control_enabled` 为锁存状态指示。真正权限通过同一帧 `TeleopTcpTarget.torso_control_enabled` 传给 IK，默认 false。消息定义已变化，更新时必须同时重新生成消息并重编译 Mapper/IK 及同工作区依赖，不混用旧版消息节点。

## 3. 启动

### 底盘无需先解锁手臂（#4469）

控制器入口的 `base_locked` 是启动时总锁，默认仍为 `true`。需要底盘移动时，在控制器启动命令中设置 `base_locked:=false`；它不是手臂解锁键。

初始化完成、全局控制允许、实时机器人反馈有效、手柄流新鲜且首次／断流重连后真实摇杆回中过，才放行底盘。手臂 WAITING、捕获、PREPARE、ACTIVE、arm_hold 以及 body 失效都不参与底盘许可判断。body 超时只清理人体通道，joy 超时停止底盘并要求重新回中；断连通知不会伪造回中。

停止、控制禁用、反馈过期、MPC 冲突和底盘总锁仍阻断输出。超过 0.2 秒无新底盘命令清除缓存；右摇杆纵轴不再触发全底盘清零。原摇杆坐标、滤波系数、加速度与速度上限保持。Mapper 与执行器在门控原因变化时打印 `[BaseGate]` 日志，可区分 `WAIT_NEUTRAL`、`JOY_STALE`、`NOT_READY`、`BASE_LOCKED`、`GLOBAL_STOP`、命令过期或无效。

终端 o／长按 A 请求被硬件受理并置 `/hardware/is_ready` 后，实机控制器执行 dev 原有启动动作：默认双臂第 5 关节各向相反方向转约 30°再返回，1.5 秒轨迹；沿用原自定义准备参数。起点取实测关节，躯干保持，执行完成才进入正常控制。服务成功日志只表示请求受理，动作开始与完成另有控制器日志。

先启动与机型一致的控制器或仿真，再在另一个交互终端启动输入。工作区和依赖准备沿用部署指南。

```bash
source /opt/ros/noetic/setup.bash
source devel/setup.bash
```

Quest：

```bash
rosrun wheel_arm_abs_vel platform_roslaunch.sh wheel_arm_abs_vel quest_velocity_ik.launch ip_address:=192.168.5.24
```

Pico：

```bash
rosrun wheel_arm_abs_vel platform_roslaunch.sh wheel_arm_abs_vel pico_velocity_ik.launch
```

Pico 默认监听 UDP 12345，收到首个合法数据包后绑定发送方 IP。在 App 选择接收电脑；默认自动枚举网卡广播机器人信息，App 通过查找机器人选择 `KUAVO`；仅需限定网卡时成对传入 `robot_ip`、`broadcast_ip`。`ip_address` 可指定头显 IP。三个参数默认空，不包含固定现场地址。广播地址与本机地址须同时设置或同时留空。

Pico 必须发送 `full_body`，只发送 `upper_body` 不满足胸部 SPINE3 映射要求。App 佩戴、连接及校准沿用官方说明。不得同时启动官方 Pico 控制服务器和本绝对式输入入口。

## 4. 参数与行为

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `enable_terminal_start` | `false` | 显式启用才开启输入终端 `o` 监听；无交互终端时提示后退出该辅助节点，其余输入节点继续运行 |
| `enable_head_control` | `true` | Quest/Pico 接收器沿用 TEST 的 VR 头控；独立跟手节点启用时自动让出发布权 |
| `preparation_arm_velocity_limit` | `1.5` | Quest/Pico 相同的准备动作手臂速度上限，可在两端入口覆盖 |
| `preparation_gain` | `4.0` | Quest/Pico 相同的准备动作增益，可在两端入口覆盖 |
| `hold_on_input_timeout` | `true` | 两个入口保持一致；断流恢复仍按原有 HOLD 和重新确认条件执行 |
| `pico_port` | `12345` | Pico UDP 接收端口 |
| `pico_peer_ip` / `ip_address` | 空 | Pico 发送方 IP；留空时由首个合法包确定 |
| `pico_advertise_ip` / `robot_ip` | 空 | 向头显广播的接收电脑地址 |
| `pico_broadcast_ip` / `broadcast_ip` | 空 | 所在网段广播地址 |
| `pico_calibration_file` | 包内 `config/pico_quest_input.yaml` | 左右手六维偏移 |

Pico 入口声明并转发 Quest 的共用控制参数，控制默认值保持一致。`input_source` 固定为 `pico`，`tracking_source_mode` 默认 `controller`；Quest 的裸手光学参数不适用于当前 Pico 协议。与增量或非轮臂配置冲突的参数仍由绝对式入口拒绝。

默认头控服务为 `/quest3/set_head_control_mode`，支持 TEST 的 `fixed`、`auto_track_active`、`fixed_main_hand`、`vr_follow`。控制器入口默认 `vr_follow`；显式设置 `head_track_hand:=true` 或 `head_control_mode:=track_hand` 时保留 beta 的独立跟手节点，并切换到 `/head_control_node/set_head_control_mode`。Pico 完整骨骼中的 Neck/Head 转为对应输入；头部姿态无效时不产生头部命令，仍可保留有效的手臂输入。

接收器从 VR 切到固定或跟手模式时，以最后发布的有效头角继续平滑；固定模式按原有角速度限制逐步回正，不从零值或旧跟手状态重新起步。模式切换与头角发布串行处理，平滑间隔使用单调时钟。头部 TF 暂缺时也保留已发布角度，避免发布未初始化的零目标。

S62 系列的 URDF 前臂与旋转工具目标映射、原生 Mapper、速度 IK、准备动作、躯干、X+A 复位、X+B 暂停恢复以及末端夹合均走同一条控制链。Pico 的原有长按拇指和 RT+Y 躯干组合保持不变。当前协议没有裸手追踪或触摸字段；按本次约定保留现有按键，暂不新增 SG100 上一个／下一个手势切换，不能把这项输入能力记为已对齐。

控制与身体数据分别做时间戳／积压检查。无效或过期输入不会重放旧的使能按键；断流后的新输入必须先释放组合键，才允许新的按下事件。`connected=true` 仅表示输入连接，不代表手臂已进入跟随。

Pico 末端力配置 GET/SET 接入共用配置处理，响应通过 Pico 原有 protobuf 返回。电流遥测保留官方 Pico 单位和字段，不把电流伪装成 Quest 接触力估计。

## 5. 验证边界

编译、隔离 ROS 的 UDP/服务/终端测试与可视仿真只证明对应软件路径。真实 Pico 佩戴校准、物理头部方向、末端拇指动作和实机跟随需要现场验证。


## Pico自动网络发现

默认不传robot_ip/broadcast_ip。接收器启动时枚举启用的IPv4广播接口，按真实子网掩码逐网卡广播KUAVO信息（UDP8443），接收端保持UDP12345。参考人形RobotInfoBroadcaster的多网卡广播方式，无需交互选择；显式参数成对提供时覆盖自动枚举。网络变化后重启输入节点。此功能不读取头显IP，不改变控制权限。

发现广播现在在独立线程中约每秒发送一次，未收到任何头显姿态时也会启动；仍使用 UDP 8443、`data.robot_name=KUAVO`、`data.robot_ip` 和 `data.eef_type`。姿态与手柄接收继续使用 UDP 12345。线程拆分保留 App 查找流程，并避免发现广播/ROS 参数查询阻塞输入接收；真实 App 和无线网络仍需现场复验。
