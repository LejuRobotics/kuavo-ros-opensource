## #4486 的原因和修复行为

旧控制器的底盘输出条件包含手臂 reference 已应用、新鲜、未 braking、authority 为 ACTIVE。手臂固定/状态切换会影响这组条件，因此底盘被一起停住。

整合版的调用链：X+B → FSM 手臂操作服务 → `ik_ros_velocity.py::_fixed_arm_operation(0)` 固定双臂；手柄轮式指令继续由 `_publish_wheel_base_command()` 与 `_base_input_ready_locked()` 单独判断。控制器 `humanoidController_wheel_absolute.cpp` 的 independent wheel channel 检查底盘锁、全局停止、初始化和指令有效期，不再用手臂 reference/braking 作底盘许可条件。

| 场景 | 预期与验证 |
| --- | --- |
| 持续按住 X+B，同时推动摇杆 | 只切换一次手臂固定；底盘持续响应 |
| 躯干启用时固定手臂 | 双臂保持，躯干继续响应 |
| 躯干关闭时固定手臂 | 保持躯干关闭，底盘仍可独立响应；生产方法回归覆盖 |
| 松开后再次 X+B | 手臂恢复跟随 |
| 急停/全局停止、底盘锁、手柄指令过期 | 仍停止底盘；生产控制器条件回归覆盖 |
| 全局停止解除后摇杆仍偏转 | 等待摇杆回中后重新响应 |

上传的 #4452 两个分包内 `/base_locked` 一直为 true，底盘命令全为零，因此这份包不能独立证明 #4486 的按键因果或验收修复。AGX 实测需先确认正常底盘使能、解除底盘锁；不能绕过急停。
