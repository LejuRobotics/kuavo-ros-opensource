## 操作入口与参数

主控和 Quest/Pico 都支持 SG100 参数。主控默认 `sg100_kp:=10 sg100_kd:=0.2 sg100_output_limit:=0.6`（已按用户后续要求与 test 对齐）；Quest/Pico 的可选覆盖值默认留空，继承主控参数。主控与遥操端的机型、末端选择必须匹配。

源码构建并 source 当前候选工作区后，下肢界面入口：

```bash
rosrun wheel_arm_abs_vel leg_joint_tui.py
```

TUI 依赖见 `scripts/requirements-tui.txt`（Textual 6.2.1）。先进入正常全身跟随，锁定躯干并用 X+B 暂停双臂，停稳后才允许提交；Esc 取消当前调整。界面用度，服务用弧度。

可选实验入口为 `quest_direct_tcp_v9_46.launch`。DirectTCP/V9 原有 30 mm / 20° 失真预算未通过，本轮没有重新完成该预算验收，不能作为已验收默认方案。

## SG100 初始化崩溃修复

部署后机型已正确传入 400062，硬件初始化完成后，SG100 初始化阶段出现段错误。空串口、独立 ROS master 的测试也能复现（退出信号 11），排除必须连接真实手才能触发的条件。旧编译对象保留了与私有实现不同版本的 SG100 头文件依赖。

将私有桥和手势库头文件改用唯一的 `wheel_arm_abs_vel/sg100/` 引用路径，重新编译所有消费者；保留转发头供未修改的 beta 仿真源码使用。新增完整 SG100 驱动初始化/退出测试，显式把左右串口设为空，不访问手部硬件。修复后初始化和正常退出通过，SG100 参数、手势、控制策略及插件装载相关回归通过。

该崩溃修复提交本身不改增益和手势配置；后续配置对齐见下一节。对照机器人上的 test/d96bcfd16，双方 SDK 和左右 joint_angle_map.json 相同。
