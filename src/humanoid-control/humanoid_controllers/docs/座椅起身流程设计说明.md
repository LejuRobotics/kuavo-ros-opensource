# Kuavo5 座椅起身流程设计说明（按键手柄改造参考）

> 适用范围：Kuavo5 代（主版本 5，如 50–56）。本文档面向后续按键/手柄交互改造，说明坐下→待命→起身的完整状态机设计思路与暴露的 ROS 接口，供手柄侧映射按键调用。

---

## 1. 设计目标

把「坐下—待命—起身」做成一个**可反复起停的循环**，满足：

- **单次触发坐到位**：一次 `sit_down` 即完整执行到最终 CSP hold（待命态），不需要反复按。
- **待命态保持 hold**：到达最终 CSP hold 后机器人锁位待命，不自动关机。
- **统一起身路径**：`stand_up` 统一走 preUpdate 重入起身（与开机 use_sit_init 起身同款轨迹），MPC 姿态可干净恢复到站立。
- **关机独立**：关机走独立 `/stop_robot`，与 sit_down/stand_up 解耦。
- **反复起停**：一次循环结束后三个状态对象全部回 IDLE，下一次 sit_down 从站立态重新串联，无残留状态。

## 2. 状态机总览

```
                  sit_down (单次触发)
  IDLE(站立,stance) ─────────────────────▶ SITTING_DOWN
  ▲                                            │
  │                                            │ /bot_sit_down_complete
  │                                            ▼
  │                                          P2 FROZEN (MPC 暂停)
  │                                            │ tickAutoAdvance (自动)
  │                                            ▼
  │                                          P3 OFFSET → OFFSET_DONE (CSP)
  │                                            │ tickAutoAdvance
  │                                       [若 seat_leg_action_enabled]
  │                                            ▼
  │                                          P4 LEG_ACTION → DONE (CSP)
  │                                            │ markSitSequenceComplete
  │                                            ▼
  │     stand_up (preUpdate 重入)         STANDBY (最终 CSP hold, 待命)
  │  ◀───────────────────────────────────────── │
  │
  │  ┌─ 段0: 复刻 HW settle 回 sit（0a 腿/腰→sit → 0b 臂→sit，CSP linear）
  │  │     └─ hold → 等 start（/hardware/is_ready，按 o / real_initial_start）
  │  └─ 段1: sit_pos → stand（standUpWbc，复用开机 boot 起身轨迹）
  │                                            │
  └────────────────────────────────────────────┘ MPC 恢复 → IDLE(站立,就绪,可走)

  关机: /stop_robot (独立, 任意态可调)
```

### 关键阶段说明

| 阶段 | 含义 | MPC 状态 | 控制 |
|------|------|----------|------|
| P1 | MPC lerp 站→坐（落座运动） | 运行 | SitReferenceManager 生成坐下轨迹 |
| P2 FROZEN | 落座终点冻结 | **暂停** | 冻结参考锁位 |
| P3 OFFSET | 座椅偏置（腿/臂 offset）平滑插值 | 暂停 | SitControlManager WBC 插值 |
| P3 OFFSET_DONE | 偏置完成 → CSP hold | 暂停 | CSP 锁位（mode=2 + kp/kd） |
| P4 LEG_ACTION | 两步腿部收脚序列（可选） | 暂停 | SitControlManager 腿部插值 |
| P4 LEG_ACTION_DONE | 收脚完成 → CSP hold | 暂停 | CSP 锁位 |
| **STANDBY** | 最终待命态 | 暂停 | CSP 锁位，等 stand_up |
| preUpdate 段0 | 实测 → 纯 sit（可选先腿后臂） | 暂停 | **CSP 关节跟踪**（mode=2，sitBootLegGain，无 WBC） |
| preUpdate 段1 | sit → stand（同开机） | 暂停→恢复 | standUpWbc 插值 |

> **收脚开关**：`seat_config_v5.json` 里 `seat_leg_action_enabled`。
> - `false`（当前默认）：P3 完成即 `markSitSequenceComplete`，停在 P3 CSP，**不收脚**。
> - `true`：P3 完成后自动进 P4 收脚序列，再 `markSitSequenceComplete`。

## 3. 自动串联设计（tickAutoAdvance）

一次 `sit_down` 触发后，落座完成（P2）由 `SitControlManager::tickFrame` 每帧调 `tickAutoAdvance` 自动推进，**无需手柄二次触发**：

```
onSitDownComplete (收到 /bot_sit_down_complete)
  → state=FROZEN, sit_auto_advance_active_=true, sit_sequence_complete_=false, MPC 暂停

每帧 tickAutoAdvance:
  FROZEN         → startOffset (P3)        [须 config_ok_]
  OFFSET_DONE    → startLegAction (P4)    [若 leg_action_config_ok_]
                 或 markSitSequenceComplete [若 P4 未启用]
  P4 完成        → markSitSequenceComplete
```

`markSitSequenceComplete` 置 `sit_sequence_complete_=true`、`sit_auto_advance_active_=false`，并通过 `publishPhaseParam` 写 `/seat_sit_sequence_complete` 参数 → 进入 **STANDBY**。

## 4. 两段式 preUpdate 重入起身

`stand_up` 不再走 MPC 反向 lerp，统一经 `humanoidController::preUpdate` 重入，分两段（与开机 use_sit_init 起身轨迹同构）：

### 段 0：HW reverse 回 sit（实机 jointMoveToPrepGoal；仿真 CSP 复刻）
对标 `hardware_sit_pose_prep` 的 reverse（与 use_sit_init HW phase2a/2b **同一服务路径**）：
- **实机**：`hardware/seat_return_reverse_prep` → `jointMoveToPrepGoal`（从当前实测出发）
  - HC 经 `publishSeatReturnReversePrepParams` → `publishHardwarePrepPlan(reverse_only)` 写 `/hardware_prep_*` 后异步调服务
  - **交接**：先切 preUpdate；`HwSeatReverse::Handoff` 期间 `fillSeatCspHoldCmd` 发实测 CSP；HW 置 `/hardware/seat_reverse_prep_active` 后 `latchCurrentJointsCsp` 再 reverse
  - reverse 完成后 `tickAwaitStandUpStart(true)` 以 sit CSP 锁位等 start
  - **失败直接中止 stand_up**，不回退 CSP
- **仿真**：无 hardware_node，仍用 CSP `mode=2` + `fillSeatCspHoldCmd` 复刻同轨迹
- **起点**：释放 hold 前的**实测关节**
- **终点**：`getSitInitialState()` 关节段（`sit_joint_pos`）
- **`reverse_leg_before_arm=true`（默认）**：
  - **0a**：腿/腰 → sit，臂保持实测；速度 **`move_speed_deg_per_s`**
  - **0b**（可选）：臂 → clear（`实测臂 + reverse_arm_clear_joint_offset_rad`）；速度 **`settle_speed_deg_per_s`**
  - **0c / 无 clear 时的 0b**：臂 → sit；速度 **`settle_speed_deg_per_s`**
- **`reverse_leg_before_arm=false`**：全身一次实测→sit，速度 `settle_speed_deg_per_s`
- 完成后可 `hold_at_sit_pose_before_stand_up_seconds`（仿真 CSP）
- **等 start（默认开）**：清 `/hardware/is_ready=0`、置 `/hardware/ready_to_start=1`；收到 `is_ready=1` 后再进段1
- 由 `seat_return.await_start_after_p5` 控制；`false` 则完成后直接段1
- 段0 期间每帧 `return true`，**不触发 MPC 完成判定**

### 段 1：纯 sit_pos → stand（复用开机 boot 起身轨迹）
- start 到时 → `reverse_seat_offset_done_=true` + `isInitStandUpStartTime_=false`（触发首帧块重算）
- **起点**：`getSitInitialState()`（纯 sit，= 段0 终点，无缝衔接）
- **终点**：`standState = getInitialState()(腿+腰) + defalutArmPosMPC_(臂)`
- **时长**：`(standState[8] - squatState[8]) / motionVel`，`motionVel` 取 `sitToStandComVelocityMps()`
- **控制**：`standUpWbc` + `sitBootLegGain`；跳过 stand_up 接触力保护
- yaw 在首帧块刷新为当前观测 yaw

### 段 1 完成 → MPC 恢复
到达 `robotStandUpCompleteTime_ + 0.8` 后：
1. `resetMpcNode(站立 target)`（target = `initial_status_` 站立态 + 当前 yaw）
2. **`pauseResumeMpcNode(false)`**（关键：重入时 MPC 曾被暂停，此处必须恢复，否则卡死）
3. spin 等 `initialPolicyReceived` → `updatePolicy` → `evaluatePolicy`
4. `isPreUpdateComplete=true`、`seat_preupdate_reentry_=false`、`seat_reentry_phase_=0`
5. 发布 `/bot_stand_up_complete` → 进入正常 `update()` 主循环，stance 就绪可走

## 5. 反复起停的复位保证

每次 stand_up 完成后，三个对象全部回 IDLE，下次 sit_down 从站立态重新串联：

| 对象 | 复位动作 | 位置 |
|------|---------|------|
| humanoidController | 复位 `isInitStandUpStartTime_/isPreUpdateComplete/is_robot_standup_complete_/is_abnor_StandUp_`；首帧块重算 `robotStartStandTime_/robotStandUpCompleteTime_`/yaw | `beginSeatReturnToPreUpdate` |
| SitControlManager | `releaseSeatResources` → `state_=IDLE`、`sit_sequence_complete_=false`、`sit_auto_advance_active_=false`、`frozen_*` 清空 | `exitSeatHoldToPreUpdate` |
| SitReferenceManager | `resetSeatLifecycleToIdle` → `seatState_=IDLE`、恢复 `/enable_pull_up_protect=true`、`/seat_sit_sequence_complete=false` | `onSeatReturnPreUpdate`（收 done 回执） |

## 6. 暴露的 ROS 接口

### 6.1 服务（手柄侧调用入口）

| 服务名 | 类型 | 方向 | 说明 |
|--------|------|------|------|
| `humanoid/sit_down` | `std_srvs/Trigger` | 手柄→SRM | **坐下**。IDLE 态触发 → 完整串联到 CSP 待命；STANDBY 态拒绝（保持 hold）；进行中态拒绝 |
| `humanoid/stand_up` | `std_srvs/Trigger` | 手柄→SRM | **起身**。STANDBY 态触发 → preUpdate 两段重入起身到站；非 STANDBY 态拒绝 |
| `humanoid_controller/seat_return_to_preupdate` | `std_srvs/Trigger` | 外部→HC | 直连起身（绕过 SRM，等同 stand_up 的底层入口） |

> `humanoid` 为 SRM 的 `nodeHandleName`（默认 `"humanoid"`，见 `SwitchedModelReferenceManager::setupSubscriptions`）。

### 6.2 话题（跨节点握手 / 状态反馈）

| 话题名 | 类型 | 发布方 | 订阅方 | 说明 |
|--------|------|--------|--------|------|
| `/bot_seat_return_preupdate` | `std_msgs/Int8` | SRM | HC | SRM→HC 触发 preUpdate 重入（stand_up 的跨节点信号） |
| `/bot_seat_return_preupdate_done` | `std_msgs/Int8` | HC | SRM | HC→SRM 回执：`1`=已释放 hold 开始重入；`0`=拒绝（运动中/未到最终 hold） |
| `/bot_sit_down_complete` | `std_msgs/Int8` | SRM | SCM | 落座完成 → SCM 进 P2 冻结 + 自动串联 |
| `/bot_stand_up_complete` | `std_msgs/Int8` | HC | 外部 | preUpdate 起身完成（`1`=成功，`-1`=失败） |
| `/stop_robot` | `std_msgs/Bool` | 任意 | controllerNodelet | **关机**：`true` → 控制器退出、电机下电（独立路径） |

### 6.3 状态参数（只读，可订阅查状态）

| 参数名 | 类型 | 含义 |
|--------|------|------|
| `/seat_control_phase` | int | 当前相位：1=P1站 2=P2冻结 3=P3偏置 4=P4收脚 |
| `/seat_p3_csp_ready` | bool | P3 CSP hold 是否就绪 |
| `/seat_sit_sequence_complete` | bool | **是否到 STANDBY 待命态**（手柄判断 stand_up 可用性的关键） |
| `/enable_pull_up_protect` | bool | 拉起保护（坐下时关，起身后恢复） |

## 7. 按键手柄映射建议

按手柄改造可直接调用上表服务，无需关心内部状态机。推荐映射：

| 手柄操作 | 调用 | 前提 | 拒绝处理 |
|---------|------|------|---------|
| 坐下键（RT+B） | `rosservice call humanoid/sit_down` | 机器人站立且 idle | 看返回 message：进行中/待命态 → 提示用户 |
| 起身键（RT+A） | `rosservice call humanoid/stand_up` | `/seat_sit_sequence_complete=true` | 返回 false 说明未到待命态，提示等待 |
| 关机键（BACK） | `rostopic pub /stop_robot std_msgs/Bool true` | 任意态 | — |

### 手柄侧最小判定逻辑

```
按下「坐下」:
  resp = call humanoid/sit_down
  if !resp.success: 语音/灯提示 resp.message   # 进行中 / 已待命

按下「起身」:
  if rosparam /seat_sit_sequence_complete == true:
      call humanoid/stand_up
  else:
      提示「坐下流程未完成，请等待」

按下「关机」:
  pub /stop_robot true
```

> 说明：手柄侧不必维护状态机副本，靠服务返回 + `/seat_sit_sequence_complete` 参数即可判定。SRM/SCM 已内置所有拒绝逻辑（运动中拒绝重复触发、未到待命拒绝 stand_up、待命态 sit_down 保持 hold 不关机）。
