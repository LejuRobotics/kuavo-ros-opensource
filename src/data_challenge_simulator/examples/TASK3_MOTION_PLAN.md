# Task 3 修改方案：按用户指令实现三指独立内撑搬运

## 1. 文档边界与目标

用户逻辑的冻结参考文件是
[`TASK3_USER_DIRECTIVE.md`](TASK3_USER_DIRECTIVE.md)。该文件仍然不修改。用户在
2026-09-15 对实施方案作出两项后续更正，本文按最新更正执行：

1. 初始化后的“一次性手掌平行桌面命令”不需要，实现中直接删除该阶段；
2. `r_little_j3` 是已授权的第五个可选手型关节，用于默认四关节方案不可行时扩大夹取搜索空间。

除这两项明确更正外，本文不能自行覆盖、修正或扩写冻结文件。后续再发生冲突时，以用户最新
明确指令为准并停止冲突实现。

本轮目标不是继续调整一组固定关节角，而是把 Task 3 改成以下状态机：

1. 初始化完成后先把右手改变为紧凑手型。
2. 从初始化实测关节直接执行一次物体相对前馈 IK，到达已确认的平掌入孔位姿；不再经过
   物体上方的第一次 IK。
3. 三根手指分别执行“逐步张开、内壁逻辑检测、单指锁存”；某指锁存后停止给它增加
   张开量。
4. 任意两根手指锁存后才锁存物体，随后通过 IK 抬起，整机移动到左侧高桌并释放。

场景尺寸、桌高和圆环位姿以当前 MJCF 的实际 numeric/body/geom 为唯一运行时来源，
配置文件不得再复制一套可能过期的场景真值。

## 2. 当前实现与用户逻辑的差异

| 阶段 | 用户逻辑 | 当前实现 | 影响 |
|---|---|---|---|
| 初始化后命令 | 用户最新更正确认一次性平掌命令不需要 | 当前没有独立的一次性平掌命令 | 当前行为可保留，不得再补该阶段 |
| 第一次 IK | 根据当前物体和机器人状态求手在物体上方；Z 可由实现选择 | 从 `task3_transfer.json` 读取固定 `right_arm_rad`，没有在线 IK | 底盘停稳误差、实测关节偏差或物体位姿变化后，固定表不能保持手—孔关系 |
| 第一次 IK 姿态 | 不存在需要继承的平掌阶段；姿态只服务于本阶段到物体上方和后续独立入孔可行性 | 旧 motion plan 额外要求保持向下插入方向 | 删除平掌继承关系，也不把后续撑开条件反向并入第一次 IK |
| 手型 | 先完成姿态变化，再下降 | 顺序基本一致 | 需要保留阶段隔离，不能把内撑条件反向混入第一次 IK |
| 下降 | 下降合适距离；只要求每根指尖有一部分进入孔内 | 执行固定关节表的逆序路径 | 没有按当前物体、实测腕姿态在线计算，也没有对“部分进入”做阶段验收 |
| 张开 | 三指逐步张开，每指触壁后独立锁存 | `control_right_internal_expansion()` 一次阻塞插值到固定 `grasp_expansion` | 先碰到的手指仍继续收到张开指令 |
| 单指锁存 | 保存每根手指的锁存状态，锁存后不再向该指发送增加张开量的命令 | C++ 每帧临时计算一个 `nearby` 集合，没有单指持久状态 | 接触可能下一帧消失，且无法表达“该指已经锁存” |
| 物体锁存 | 任意两根手指分别锁存后，物体才跟手 | 当前代码要求某一帧有任意两指同时进入间隙后直接锁存物体 | 缺少用户要求的“单指锁存 → 两指物体锁存”因果顺序 |
| 无冲量顺序 | 先张开，逻辑检测后锁存；不允许先产生接触冲量再锁存 | 使能后先关闭三指碰撞，再做几何间隙检测 | 原理可复用，但要证明关闭碰撞发生在第一条张开增量命令之前 |
| 手指轨迹 | 默认使用既定四关节；默认方案不可行时，允许把 `r_little_j3` 作为第五个可选自由度 | 当前始终让 `little_j3` 执行 `-0.5 → 0` | 第五关节本身不违规，但应从“固定必动”改成“按可行性启用” |
| 抬升 | 物体锁存后通过 IK 抬手和物体 | 使用预存固定关节路径 | 不是从锁存后的实测状态做 IK |
| 横移与释放 | 整机移动到左侧桌，最后释放 | 已有按目标桌位置修正底盘和逻辑释放的框架 | 可保留框架，但目标和落桌高度必须读取当前场景，且前提必须是新两指锁存完成 |
| 验收 | 每阶段按用户语义独立成立 | 当前离线门主要证明固定关节表和固定展开量 | 离线 PASS 不能证明当前用户状态机已实现 |

另外，当前 `TASK3_MOTION_PLAN.md` 的旧内容写的是源/目标桌面 `0.65/0.85 m`，而当前
`task3.xml` 和 `task3_transfer.json` 实际是 `0.90/1.10 m`。
本方案不擅自选择其中一组旧数值，而是消除配置重复：运行与审计都从场景读取实际值。

## 3. 修改后的状态与接口

### 3.1 状态机

`task3.py` 只允许按下列顺序前进：

```text
INITIALIZE
  -> COMPACT_HAND
  -> SECOND_IK_INTO_BORE
  -> ARM_FORCE_FREE_EXPANSION
  -> EXPAND_AND_LATCH_FINGERS
  -> OBJECT_LATCHED
  -> LIFT_BY_IK
  -> MOVE_BASE_TO_LEFT_TABLE
  -> LOWER_BY_IK
  -> RELEASE
  -> SETTLED
```

任何阶段失败都停止后续动作并写入 `task_result.txt=fail`。不得为了让后续阶段通过而回改
前一阶段已经验收的目标语义，例如不能因手指未碰壁就把第一次 IK 偷换成“同时满足撑开”的
联合求解。

### 3.2 单指状态

C++ follower 为 `index`、`middle`、`little` 各保存：

- `SEARCHING`：允许任务脚本发送小幅增加张开量的保持目标；
- `LATCHED`：首次进入有效内壁间隙时保存该指实际关节位置，之后保持该位置；
- `RELEASING`：收到释放命令后允许收拢，直到离开内壁带。

新增只读反馈话题：

- `/mujoco/task3_hollow_cylinder/internal_finger_latch_mask`
  （`std_msgs/UInt8`，bit 0/1/2 分别表示食指/中指/小指）；
- 保留 `/mujoco/task3_hollow_cylinder/internal_grasped` 作为物体是否锁存的汇总结果；
- 保留 `/mujoco/task3_grasp_enabled` 作为进入无冲量内撑阶段、以及布防释放的命令。

不用物理接触消息作为锁存依据。几何检测使用指垫 box 对有限圆柱内壁的解析间隙，且每根
指垫只需有一部分处于圆柱有效高度内，不增加“整块指垫进入”或“三点同高”约束。

### 3.3 手指命令规则

默认紧凑姿态使用以下四个右手关节：

- `r_index_j2 = 1.55`；
- `r_middle_j1 = 1.65`；
- `r_little_j1 = 3.0`；
- `r_little_j2 = 1.8`。

默认张开时仅改变 `r_index_j2`、`r_middle_j1`、`r_little_j2`；
`r_little_j1` 固定为 `3.0`，拇指及其余关节保持 `0`。
理论终点分别为 `1.0`、`1.1`、`1.0`，但它们只是搜索上限，不是必须发送的统一终点。

如果默认四关节搜索无法得到有效的独立两指锁存窗口，则直接启用已经授权的第五个可选关节
`r_little_j3`。它应作为独立搜索维度参与紧凑姿态和张开轨迹求解，而不是无条件固定执行当前
的 `-0.5 -> 0`。搜索范围先受模型关节限位约束，再由碰撞检查收窄；最终值必须由扫描结果
确定。除这五个关节外，拇指和其余未列出关节保持 `0`。

任务脚本以小步长循环：读取锁存 mask，只给仍为 `SEARCHING` 的手指增加张开量；已经
`LATCHED` 的手指继续发送其锁存位置作为保持目标，不再发送更大的张开目标。每一步都先等待
新 mask 或超时，再决定下一步。任意两位变为 1 后立即停止所有继续张开动作并等待
`internal_grasped=true`。

### 步骤 2：实现 C++ 单指逻辑锁存

修改：

- `src/mujoco/src/mujoco_node.cc`

动作：

1. 将三枚指垫从无序集合改成固定顺序数组，建立指垫、手指名和受控关节地址的明确映射。
2. 在 `InternalContactFollowerState` 中增加三位锁存状态、每指锁存关节位置和上次发布 mask。
3. `/mujoco/task3_grasp_enabled=true` 到达时，先关闭三枚活动指垫与圆环的碰撞，再允许几何检测；
   该先后顺序必须在同一仿真线程内确定，不能依赖 ROS 回调与手指命令的偶然时序。
4. 每帧分别检查三指。某指第一次进入有效内壁间隙时，将其置为 `LATCHED` 并保存实测关节
   位置；锁存状态不能因下一帧间隙变化而自动丢失。
5. 对已锁存手指覆盖其位置执行器目标为保存值，作为通信延迟期间的安全保持；不得推动它
   越过锁存位置。
6. 每次 mask 改变时发布 `UInt8`；当锁存位数达到 2 时，保存圆环相对 `r_hand_base` 的完整
   SE(3)，再发布 `internal_grasped=true`。
7. 显式释放后切换到 `RELEASING`。保留“至少两指离开才解除物体锁存”的现有释放原则，
   但清空单指锁存必须发生在释放状态，不得在持取中因抖动清空。
8. object reset 时统一恢复物体碰撞、指垫碰撞、三指 mask、held/falling/settled 状态。

验收门：用确定性仿真配置依次制造 `index`、`little` 进入间隙，必须观察到 mask
`000 -> 001 -> 101`，且只有 `101` 后 `internal_grasped` 才变为 true。交换接触顺序也应通过；
单独一指锁存永远不能锁存物体。

3. 复用现有底盘速度和位置容差控制器，停稳后接受实测底盘位姿。
4. 底盘移动期间保持抬升后的右臂和三指独立锁存状态。

验收门：停稳后圆环外圆投影完整在目标桌 footprint 内；全过程 `internal_grasped` 保持 true。

### 步骤 10：在线 IK 下降并释放

修改：

- `examples/task3.py`
- `src/mujoco/src/mujoco_node.cc`

动作：

1. 从停稳后的实测底盘和右臂状态重新求下降 IK，使圆环最低点到目标桌面上方的释放高度。
2. 完整检查下降路径后执行，不复用源桌固定关节表。
3. 发布 `/mujoco/task3_grasp_enabled=false` 布防释放。
4. 三指从各自锁存角独立收回紧凑值；不假定三指锁存角相同。
5. 至少两指离开内壁带后 follower 解除物体锁存，圆环从静止开始无碰撞自由落下。
6. 圆环投影完整位于目标桌内且最低点到达桌面时，沿用逻辑落桌并清零六维速度。
7. 指垫获得配置净空后恢复指垫碰撞；圆环碰撞只在显式 reset 时恢复。

验收门：释放前圆环未接触桌面；释放和落桌无接触冲量；最终
`internal_grasped=false`，圆环最低点等于从当前场景读取的桌面高度，线速度和角速度均为零。

## 5. 实施顺序与停止条件

严格按步骤 1 至 11 实施。每一步先通过自己的离线或小范围运行验收，再开始下一步。
以下情况必须停止，不能使用 fallback 绕过：

- 默认四关节模式失败后，已启用 `r_little_j3` 的五关节模式仍找不到两指独立锁存窗口；
- 第一次 IK 可达，但独立下降阶段找不到三指部分入孔且无禁止碰撞的路径；
- 单指逻辑锁存需要新增用户未授权的物理力、接触冲量或外侧夹取；
- 当前 MJCF 的实际桌高/位置需要改动才能继续，而用户没有授权改场景；

遇到这些情况时，只报告失败点、证据和对后续流程的影响，并就具体场景或逻辑变更请求用户
确认。
