# Scene 1 IK 定义

本文只描述 `./run-scene1.sh task` 当前实际使用的 IK 定义。后续判断“目标点是否正确”，统一按这里的坐标系和点来判断。

## 1. 三个必须区分的坐标/点

### 世界坐标系 `W`

圆柱、目标框和机器人各刚体的 `/mujoco/<body>/pose` 都在 MuJoCo 世界坐标系下。代码中的 `grasp_tcp_world` 和 `drop_tcp_world` 也都属于这个坐标系。

### IK 根坐标系 `I`

本场景的 IK 只加载 `biped_v3_upper_body.urdf`。该文件的根节点名字仍叫 `base_link`，但它省略了轮式底盘、腿和腰，左右肩直接挂在根节点下。因此，它在整机几何中对应的是 **`waist_yaw_link`，不是底盘的 `base_link`**。

`task1.py` 现在订阅 `/mujoco/waist_yaw_link/pose`，每次求解前用实时腰部位姿把世界目标变到 IK 根坐标系：

```text
p_I = R_WI^-1 * (p_W - t_WI)
R_ITCP = R_WI^-1 * R_WTCP
```

这里 `t_WI`、`R_WI` 是 `waist_yaw_link` 在世界系下的位置和方向。`/odom` 中底盘 `base_link` 的位姿不再用于 Scene 1 的 IK 目标转换。

### `r7`、当前手掌中心与历史 IK 末端

当前 IK 约束帧是：

```text
zarm_r7_end_effector
```

黑漫右手的 `r_hand_base` 相对 `zarm_r7_link` 是 `xyz = [0, 0, -0.07]`，并绕 X 旋转 π。对当前 `r_hand_base.STL` 做静态包围盒计算，mesh 中心在 `r_hand_base` 局部约为 `[0.000067, -0.016679, 0.062586] m`，即在 `zarm_r7_link` 系约为：

```text
right_palm_mesh_center_in_r7 = [0.000067, 0.016679, -0.132586] m
right_ik_eef_in_r7           = [0.000067, 0.016679, -0.132586] m
```

也就是说，当前 URDF 已把右臂 `zarm_r7_end_effector` 规范为手掌 mesh 的几何中心；`eef_z_offset = 0`，IK 节点没有再叠加位置补偿。该固定关节的旋转仍为零，所以 EEF 方向仍等于 `zarm_r7_link` 的方向。

历史定义是 `right_ik_eef_in_r7 = [0, 0, -0.17] m`，与手掌 mesh 中心相距约 `0.041 m`。MuJoCo 中的 `r_arm_ft_frame` 仍位于这个历史位置，因为它同时是力/力矩传感器参考点，本轮没有移动它。它不再等于当前 IK EEF，也不能再用它判断手掌中心是否到达目标。

当前 IK 末端是手掌 mesh 的**几何中心**，仍不等于经过抓取标定的“两指夹持中心”。后续若要改成真正夹持中心，必须提供或标定 `zarm_r7_end_effector → grasp_center` 的固定变换。

## 2. 抓取与投放目标

圆柱和目标框话题给出各自 body 原点，当前任务目标是：

```text
grasp_tcp_world = cylinder_body_origin_world + [0, 0, 0.100]
drop_tcp_world  = target_bin_body_origin_world + [0, 0, 0.150]
```

`GRASP_Z_OFFSET=+0.100 m`，受控 EEF 位于圆柱中心正上方 `10 cm`。旧投放目标只在台面上方 `0.010 m`，手心朝下时会让指尖插入桌面或箱底；现在 `DROP_Z_OFFSET=+0.150 m`，投放 TCP 世界 Z 为 `0.800 m`，高于 `0.7025 m` 箱口。这个 EEF 当前定义为手掌 mesh 几何中心，不是两指夹持中心。

TCP 方向不再使用从旧任务复制来的固定四元数。三段 ready 关节运动结束后，代码读取当前 14 个手臂关节，用本机 FK 得到当前右 TCP 方向，再把它转换到世界系。抓取和投放都保持这个世界方向。这样第一次 IK 目标的方向从当前可达姿态出发，不会先强迫机械臂满足另一台机器人/另一场景的手腕方向。

### 圆柱随机区域为什么必须收回

下部关节为零时，`waist_yaw_link` 世界位置由完整模型固定链得到约 `[0.11575, 0, 0.96316] m`；右肩相对腰部为 `[0, -0.2527, 0.242] m`，所以右肩世界位置约为 `[0.11575, -0.2527, 1.20516] m`。

按当前手掌中心 EEF 计算，从右肩到 `zarm_r7_end_effector` 的各段固定长度相加，理论最大链长约 `0.675 m`。这是只看长度、不考虑关节限位和姿态的乐观上限。历史 `-0.17 m` EEF 对应的旧估算约为 `0.711 m`，不能继续拿来判断当前目标。

旧随机区域的抓取 TCP 距右肩约 `0.71 m`，超出当前手掌中心 EEF 的真实位置可达上限。现在两个区域移到来源箱靠机器人一侧；计入 `+0.100 m` 抓取高度后，抓取 TCP 距右肩约 `0.62 m`：

```text
cylinder_1: X=[0.575, 0.585], Y=[-0.285, -0.265]
cylinder_2: X=[0.575, 0.585], Y=[-0.205, -0.185]
```

计入圆柱 `0.025 m` 半径后，最近外沿为 `X=0.550 m`，正好不穿过来源箱内侧壁；两区域的最小中心间距为 `0.060 m`，大于圆柱直径 `0.050 m`。

当前圆柱中心 Z 为 `0.685 m`，抓取 EEF 请求 Z 为 `0.785 m`。

### 当前桌面与箱体几何

- 桌面顶面：`Z=0.65 m`，平面范围 `X=[0.42,1.38] m`、`Y=[-0.64,0.32] m`。
- 小目标箱：中心 `(0.53,-0.528,0.65) m`；世界平面外边界为 `X=[0.42,0.64] m`、`Y=[-0.64,-0.416] m`。
- 大来源箱：中心 `(0.73,-0.196,0.65) m`，世界平面外边界为 `X=[0.53,0.93] m`、`Y=[-0.416,0.024] m`。
- 小箱内部平面边界：`X=[0.44,0.62] m`、`Y=[-0.62,-0.436] m`；箱底顶面 `Z=0.665 m`、墙顶 `Z=0.7025 m`。
- 圆柱高 `0.040 m`，落在箱底后的中心 Z 为 `0.685 m`，会比墙顶高 `0.0025 m`。当前脚本的完整三维包含判定仍有空 Z 区间；本轮只修 IK 目标，没有修改完成判定。

上述数值均以当前 `task1.xml` 为准。

## 3. IK 求解约束

每次求解都显式使用以下规则：

- `arm_q0`：求解瞬间读取的 14 个实际手臂关节角，而不是 IK 节点内部缓存或 URDF 默认角。
- 右臂目标：上面定义的任务 TCP 世界位姿转换到 `waist_yaw_link` 后的位姿。
- 左臂目标：由同一份当前关节角做 FK 得到，目的是让双臂 IK 服务保持左臂当前状态。
- `constraint_mode = 2`：位置硬约束、方向软代价。
- 位置容差：`0.001 m`。
- 方向软代价权重：`0.011`。它不是必须精确满足的方向容差。
- 位置代价权重字段显式填为 `10.0`，避免 SDK 的 `0.0` 默认值产生歧义；在 `constraint_mode = 2` 下，TCP 主位置项走硬约束，最终位置由 `0.001 m` 的硬约束决定，并不靠这个权重拉近。
- 最大主迭代次数：`50`。
- 求解返回后立即用同一 IK 模型做 FK 复核；受控 TCP 的位置误差超过 `0.002 m` 就拒绝执行该关节解，不能再把“服务返回了关节角”当成“已经到目标点”。

位置是抓取任务真正需要对齐的量，因此它是硬约束；方向只用于偏好保持 ready 手腕方向，不能再因为旧四元数不可达而把位置求解堵死。

## 4. 不属于当前 IK 的约束

Scene 1 的圆柱、桌面、目标框及其碰撞几何不会进入这个 IK。IK 节点只加载机器人上半身 URDF，当前 `plantIK.cc` 也没有添加场景碰撞或最小距离约束。因此“物体碰撞导致 IK 无解”不是当前代码路径的原因；碰撞只会在 MuJoCo 执行动作时发生。

IK 的关节范围仍来自 `biped_v3_upper_body.urdf`。本次没有扩大这些范围，因为修改公共 IK 模型会影响 Scene 1 之外的调用；若目标在上述坐标和 TCP 定义修正后仍超出范围，应单独核对并统一 IK URDF 与仿真 MJCF 的关节限位。

## 5. 初始化现在表示什么

初始化只包含三段右臂关节运动，不再把 `knee_joint` 从 `0` 改到 `0.1`。插值序列包含最终目标点；ready 后等待固定 `0.2 s`，再读取实际关节状态作为 FK 输入和首次 IK 初值。本轮没有增加关节误差门槛。
